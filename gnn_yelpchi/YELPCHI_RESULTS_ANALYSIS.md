# YelpChi 데이터셋 실험 결과 분석

## 📋 개요

본 문서는 **YelpChi 참고 데이터셋**에서 진행한 10개 GNN 모델 비교 실험 결과를 분석하고, 그 해석을 정리한 보고서이다. 이는 본 프로젝트의 메인 데이터셋인 YelpZip 실험에 더해, 제안 모델의 **확장성 검증** 목적으로 수행되었다.

---

## 1. YelpChi 데이터셋 특성

### 1.1 데이터셋 위치

YelpChi는 YelpZip과 마찬가지로 리뷰를 노드로 정의하는 **리뷰 네트워크 데이터셋**이다. 따라서 메인 실험(YelpZip)과 동일한 노드 정의를 가지므로, 제안 모델의 확장성을 검증하기에 적합한 참고 데이터셋이다.

### 1.2 관계 구조

| 관계 | 의미 |
|------|------|
| **R-U-R** | 같은 사용자가 작성한 리뷰 간 연결 |
| **R-T-R** | 같은 식당에 같은 기간에 작성된 리뷰 간 연결 |
| **R-S-R** | 같은 식당에 같은 별점을 준 리뷰 간 연결 |

### 1.3 메인(YelpZip)과의 비교

| 항목 | YelpZip (메인) | YelpChi (참고) |
|------|---------------|---------------|
| **노드** | 리뷰 (Review) | 리뷰 (Review) |
| **관계 수** | 6개 (R-U-R, R-T-R, R-S-R + 커스텀 3개) | 3개 (R-U-R, R-T-R, R-S-R) |
| **목적** | 메인 모델 학습/평가 | 제안 모델 확장성 검증 |

---

## 2. 실험 결과

### 2.1 주요 모델 성능

| 모델 | PR-AUC | ROC-AUC | Macro-F1 |
|------|-------:|--------:|---------:|
| MLP | 0.4748 | 0.8085 | 0.6765 |
| **V8 (제안)** | **0.5864** | **0.8874** | **0.7445** |
| **V9 (제안)** | **0.5735** | **0.8708** | **0.7252** |
| SAGE | 최고 수준 | 최고 수준 | 최고 수준 |
| TAG | 최고 수준 | 최고 수준 | 최고 수준 |

### 2.2 제안 모델 V8/V9 vs MLP 비교

V8 모델은 MLP 대비 다음과 같은 성능 향상을 보였다:

| 지표 | MLP | V8 | 향상 |
|------|----:|---:|----:|
| PR-AUC | 0.4748 | 0.5864 | **+0.1116** |
| ROC-AUC | 0.8085 | 0.8874 | **+0.0789** |
| Macro-F1 | 0.6765 | 0.7445 | **+0.0680** |

V9 모델도 동일하게 MLP보다 전반적으로 높은 성능을 기록하였다.

---

## 3. 결과 해석

### 3.1 보고서용 본문

YelpChi 데이터셋을 활용한 확장성 실험에서는 본 프로젝트에서 제안한 V8, V9 모델이 기존 feature-only 방식인 MLP보다 높은 성능을 보였다. V8은 PR-AUC 0.5864, ROC-AUC 0.8874, Macro-F1 0.7445를 기록하였고, V9은 PR-AUC 0.5735, ROC-AUC 0.8708, Macro-F1 0.7252를 기록하였다. 이는 MLP의 PR-AUC 0.4748, ROC-AUC 0.8085, Macro-F1 0.6765보다 전반적으로 높은 결과이다.

특히 V8은 MLP 대비 PR-AUC에서 0.1116, ROC-AUC에서 0.0789, Macro-F1에서 0.0680 향상되었다. 이는 제안 모델이 단순 노드 feature만을 활용하는 방식보다 **리뷰 간 관계 구조를 함께 학습했을 때 더 나은 탐지 성능을 보일 수 있음**을 의미한다.

다만 YelpChi 실험에서 가장 높은 성능은 SAGE와 TAG 계열 모델에서 나타났다. 따라서 본 실험 결과는 제안 모델 V8, V9이 기존 MLP나 일부 GNN baseline보다 개선된 성능을 보였다는 점에서 **확장 가능성을 확인한 결과**로 해석할 수 있지만, **모든 GNN 모델을 압도했다고 보기는 어렵다**. 향후에는 V8, V9 구조에 GraphSAGE나 TAG 계열의 이웃 집계 방식을 결합하거나, relation별 가중치 조정 및 threshold 최적화를 통해 추가적인 성능 개선이 필요하다.

### 3.2 표 아래 들어갈 짧은 해석

> 제안 모델 V8과 V9은 YelpChi 데이터셋에서 MLP 대비 높은 PR-AUC, ROC-AUC, Macro-F1을 기록하였다. 이는 제안 모델이 단순 feature 기반 분류보다 리뷰 간 관계 정보를 활용하는 구조에서 더 나은 탐지 성능을 보일 수 있음을 의미한다. 다만 SAGE와 TAG가 가장 높은 성능을 기록하였으므로, 향후 제안 모델에 이웃 집계 방식 개선 및 relation별 가중치 조정 기법을 추가할 필요가 있다.

## 4. 발표용 요약

> YelpChi 확장 실험에서는 저희가 제안한 V8, V9 모델도 의미 있는 성능을 보였습니다.
>
> V8은 PR-AUC 0.5864, ROC-AUC 0.8874, Macro-F1 0.7445를 기록했고, V9은 PR-AUC 0.5735, ROC-AUC 0.8708, Macro-F1 0.7252를 기록했습니다.
>
> 특히 MLP가 PR-AUC 0.4748이었던 것과 비교하면, V8과 V9 모두 feature만 보는 모델보다 높은 성능을 보였습니다. 이는 저희 모델이 리뷰 간 관계 정보를 활용했을 때 탐지 성능을 개선할 수 있다는 가능성을 보여줍니다.
>
> 다만 SAGE와 TAG 모델이 더 높은 성능을 보였기 때문에, 제안 모델이 모든 baseline을 압도했다고 말하기보다는, 기존 MLP 대비 개선 효과와 다른 리뷰 네트워크 데이터셋으로의 확장 가능성을 확인한 결과로 해석했습니다.

## 5. Amazon과 묶어서 작성하는 경우

확장성 실험에서는 **YelpChi와 Amazon**을 함께 참고하였다.

YelpChi에서는 제안 모델 V8과 V9이 MLP보다 높은 성능을 보여, **리뷰 간 관계 구조를 활용하는 방식이 feature-only 방식보다 효과적일 수 있음**을 확인하였다.

반면 Amazon에서는 V8과 V9 역시 높은 성능을 보였지만, **MLP도 PR-AUC 0.9158 수준의 높은 성능**을 기록하였다. 이는 Amazon 데이터셋의 경우 그래프 구조뿐 아니라 개별 사용자 feature 자체의 구분력이 강하게 작용했을 가능성을 의미한다.

따라서:
- **YelpChi 결과**: 제안 모델의 리뷰 네트워크 기반 확장 가능성을 보여주는 근거
- **Amazon 결과**: 데이터셋 특성에 따라 GNN의 효과가 달라질 수 있음을 보여주는 보조 분석 사례

## 6. 보고서 작성 가이드

### ❌ 사용하지 말아야 할 표현

> V8/V9이 모든 모델을 압도했다.
> SAGE가 최고였으므로 우리 모델은 의미가 없다.

→ 둘 다 잘못된 표현. 정확한 위치 설정이 필요함.

### ✅ 권장 표현

> 제안 모델 V8·V9이 기존 feature-only 모델(MLP)보다 높은 성능을 보였고, 일부 강한 GNN baseline과 경쟁 가능한 수준이었다. 다만 SAGE/TAG가 더 높아 향후 개선 여지가 있다.

이 표현이 가장 안전하고 설득력이 있다.

## 8. 결론

> **V8·V9은 YelpChi에서 최고 모델은 아니지만, MLP보다 확실히 높은 성능을 보여 "리뷰 관계 기반 제안 구조의 확장 가능성"을 입증한 결과로 해석하는 것이 가장 좋다.**

| 항목 | 내용 |
|------|------|
| **데이터 특성** | 리뷰 노드 기반, YelpZip과 동일 구조 |
| **실험 목적** | 제안 모델 확장성 검증 |

| **한계** | SAGE/TAG가 더 높음 → 향후 개선 방향 |
| **활용 위치** | 확장성 검증 및 향후 개선 방향 근거 |

## 9. 향후 개선 방향

YelpChi 실험에서 SAGE/TAG가 더 높은 성능을 보였으므로, 다음과 같은 개선이 가능하다:

1. **이웃 집계 방식 결합**: V8/V9 구조에 GraphSAGE의 sampling 방식이나 TAG의 polynomial filter를 결합
2. **Relation별 가중치 조정**: 각 관계의 중요도를 더 세밀하게 학습
3. **Threshold 최적화**: validation set 기반 best threshold 적용
4. **Attention 메커니즘 강화**: 노드 간 attention으로 더 정밀한 관계 학습
